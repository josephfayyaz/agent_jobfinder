# Phase P4r — Cloud BYOK Provider Onboarding

## Goal

Replace the older OpenAI-only onboarding idea with a provider onboarding flow that
fits Job Agent's actual product direction:

1. **Cloud BYOK is the default path** for mainstream users.
2. **OpenAI is recommended**, but Claude is fully supported.
3. **Local providers remain advanced options**, not the default public path.
4. Model roles are presented in product language:
   - **Fast model** = scoring, extraction, lightweight analysis
   - **Writer model** = CV drafts, cover letters, outreach
5. The app must clearly explain the billing truth:
   - ChatGPT subscription != OpenAI API credits
   - Claude subscription != Anthropic API credits

This phase must also normalize provider mode handling across the app before any
Ollama work lands.

---

## Product rules

- Do **not** make the app feel OpenAI-only.
- Do **not** force local LLMs into the main onboarding happy path.
- Do **not** block the future addition of LM Studio + Ollama + mixed mode.
- Do **not** store secrets in plaintext YAML if keyring is available.

Preferred user-facing framing:

- `Connect your AI provider`
- `Recommended: OpenAI`
- `Also supported: Claude`
- `Advanced: Local model`

Avoid exposing the phrase `BYOK` in the UI. It is acceptable in internal specs only.

## Part 1: Normalize provider modes

Current drift exists because provider mode logic is duplicated across router/UI
helpers. Introduce a shared helper module, for example:

`job_agent/providers.py`

It should contain:

- `normalize_provider_mode(value: str | None) -> str`
- `provider_setup_status() -> dict[str, object]`
- `provider_display(mode: str) -> tuple[str, str]`

Allowed normalized values:

- `openai`
- `anthropic`
- `lm_studio`
- `ollama`
- `mixed`

Legacy value:

- `local` → normalize to `lm_studio`

All of these files must use the shared normalization:

- `job_agent/llm.py`
- `job_agent/routers/system.py`
- `job_agent/routers/setup_state.py`
- `job_agent/routers/ui_context.py`

## Part 3: Provider validation endpoint

Add a dedicated endpoint in `job_agent/routers/system.py`:

`POST /providers/validate`

Accept JSON like:

```json
{
  "provider_mode": "openai",
  "openai_api_key": "sk-...",
  "anthropic_api_key": "",
  "lm_studio_base_url": "http://localhost:1234/v1",
  "ollama_base_url": "http://localhost:11434"
}
```

Behavior:

- `openai`: require key present and validate connectivity with a fast provider check
- `anthropic`: require key present and validate connectivity with a fast provider check
- `lm_studio`: confirm `/models` is reachable
- `ollama`: confirm `/api/tags` is reachable
- `mixed`: valid if at least one local provider is reachable or one cloud key is valid

Return:

```json
{
  "ok": true,
  "provider_mode": "openai",
  "detail": "OpenAI key accepted."
}
```

or

```json
{
  "ok": false,
  "provider_mode": "anthropic",
  "detail": "Anthropic key missing or invalid."
}
```

This endpoint is for UX validation only. It must **not** save settings.

## Part 4: Add AI provider health endpoint for banners

Add:

`GET /health/ai-status`

Return:

```json
{
  "configured": true,
  "ready": true,
  "provider_mode": "openai",
  "openai_ready": true,
  "anthropic_ready": false,
  "lm_studio_ready": false,
  "ollama_ready": false
}
```

This powers a top-level warning banner in the base template.

## Part 5: Onboarding UX

Update `frontend/templates/onboarding.html` and `frontend/static/onboarding.js`.

### Required structure

Step 1 must be **AI provider setup**.

Suggested order:

1. AI
2. Profile
3. Facts
4. Questions
5. Search

### Step-1 content

Show four choices:

- OpenAI — recommended
- Claude
- LM Studio — advanced / local
- Ollama — advanced / local

Show a concise note:

- `Keys stay on this machine`
- `You pay the provider directly`

For OpenAI and Claude, add compact "how to get a key" help drawers linking to
their console pages and explicitly stating billing is separate from chat subscriptions.

Do **not** bury that billing truth in Settings only; it must appear in onboarding.

### Validation flow

Button label:

`Validate & Continue`

Flow:

1. Call `POST /providers/validate`
2. If valid:
   - save settings via `POST /settings/save`
   - move to step 2
3. If invalid:
   - show inline error
   - do not continue

### Mixed mode

Do **not** expose `mixed` in onboarding. Keep it as an advanced Settings choice.

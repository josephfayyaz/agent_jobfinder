# Phase UI2 — Analytics Dashboard (/ui/analytics)

## Goal

Add an analytics dashboard at `/ui/analytics` that surfaces:
1. Application funnel (conversion rates at each stage)
2. CV score distribution
3. Top missing skill gaps (from rejection analytics)
4. Weekly application activity
5. Posting velocity (companies adding most new jobs lately)

All data comes from existing services — no new DB models or LLM calls.

---

## Hard Rules

- No Alembic. Never create venvs. Always conda ML.
- Starlette TemplateResponse keyword args only.
- No new ORM models.
- `RejectionAnalyticsService` raises `ValueError("insufficient_data")` if fewer than 5
  non-pending applications exist — handle gracefully: show a friendly empty state.

---

### Posting Velocity (existing endpoint logic)

Reuse the same query used by `GET /analytics/posting-velocity`. In the route handler,
call it inline — do NOT call the existing HTTP endpoint from within Python; query
directly:

```python
from datetime import datetime, timedelta, timezone
from job_agent.models import CareerPageScanLog, CareerPageSource

days = 7
cutoff = datetime.now(timezone.utc) - timedelta(days=days)
logs = (
    db.query(CareerPageScanLog)
    .filter(CareerPageScanLog.scanned_at >= cutoff)
    .order_by(CareerPageScanLog.new_jobs.desc())
    .limit(10)
    .all()
)
velocity = []
for log in logs:
    source = db.get(CareerPageSource, log.source_id)
    velocity.append({
        "company": source.company if source else "unknown",
        "new_jobs": log.new_jobs,
        "scanned_at": log.scanned_at.strftime("%d %b %Y %H:%M"),
    })
```

## What to Implement

### 1. New route in `job_agent/main.py`

Place after the `GET /analytics/rejection-patterns` endpoint (around line 1688).

```python
@app.get("/ui/analytics", include_in_schema=False)
def ui_analytics(request: Request, db: Session = Depends(get_db)):
    from job_agent.services.rejection_analytics import RejectionAnalyticsService
    from datetime import datetime, timedelta, timezone

    analytics = None
    insufficient = False
    try:
        analytics = RejectionAnalyticsService().aggregate(db)
    except ValueError:
        insufficient = True

    # posting velocity — last 7 days
    cutoff = datetime.now(timezone.utc) - timedelta(days=7)
    logs = (
        db.query(CareerPageScanLog)
        .filter(CareerPageScanLog.scanned_at >= cutoff)
        .order_by(CareerPageScanLog.new_jobs.desc())
        .limit(10)
        .all()
    )
    velocity = []
    for log in logs:
        source = db.get(CareerPageSource, log.source_id)
        velocity.append({
            "company": source.company if source else "unknown",
            "new_jobs": log.new_jobs,
            "scanned_at": log.scanned_at.strftime("%d %b %Y %H:%M"),
        })

    return templates.TemplateResponse(
        request=request,
        name="analytics.html",
        context={
            "analytics": analytics,
            "insufficient": insufficient,
            "velocity": velocity,
        },
    )
```

Add `CareerPageScanLog` and `CareerPageSource` to imports at the top of main.py if not
already imported (they are already imported for the posting-velocity endpoint).

### 2. New template `job_agent/templates/analytics.html`

Extends `base.html`. Layout:

```
┌─ Header ──────────────────────────────────────────────┐
│  Analytics                                            │
└───────────────────────────────────────────────────────┘

[If insufficient=True]
┌─ Empty state ─────────────────────────────────────────┐
│  "Not enough data yet. Apply to at least 5 jobs to    │
│   unlock analytics."                                  │
└───────────────────────────────────────────────────────┘

[If analytics available — 2 column grid on xl]
┌─ Funnel card ──────┐  ┌─ Score distribution card ───┐
│  stage: count (%)  │  │  bar per bucket              │
└────────────────────┘  └─────────────────────────────┘

┌─ Skill Gaps card ──┐  ┌─ Weekly Activity card ───────┐
│  keyword: N misses │  │  week: bar with count         │
└────────────────────┘  └─────────────────────────────┘

┌─ Posting Velocity (full width) ───────────────────────┐
│  company | new jobs | scanned at                      │
└───────────────────────────────────────────────────────┘
```

**Funnel card:**
Stages in order: discovered → applied → responded → offer → rejected.
For each stage show count. Compute and display conversion rate from applied → responded.
Style: vertical list with a colored left border per stage
(blue=discovered, indigo=applied, yellow=responded, green=offer, red=rejected).

**Score distribution card:**
Four buckets: 90-100, 75-89, 50-74, below-50.
Render each as a labeled bar using Tailwind width classes:
- Get max bucket count; for each bucket: width percentage = count / max * 100 (cap at 100).
- Use `style="width: Xpx"` (not dynamic Tailwind class — Tailwind CDN purge won't work with dynamic class names).
- Colors: 90-100 green, 75-89 indigo, 50-74 yellow, below-50 red.

**Skill Gaps card:**
Show top 8 `skill_gaps` as `keyword (N misses)` in a simple list.
If empty: "No gaps detected yet."

**Weekly Activity card:**
Show last 8 weeks from `weekly_activity` list as a small table:
week | count (as a number).
If empty: "No weekly data."

**Posting Velocity table:**
Full-width table: Company | New Jobs | Scanned At.
If `velocity` is empty: "No scans in the last 7 days."

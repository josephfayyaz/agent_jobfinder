SECTION 4 — FIELDS WITH NO ORM COLUMN (store or ignore)
================================================================

These schema fields have no dedicated ORM column. Handle as follows:

  completion_status     → Store as JSON in MatchProfile.seniority_estimate
                          under key "completion_status", OR add a new
                          String(20) column to Candidate: completion_status.
                          RECOMMENDED: add Candidate.completion_status column
                          to models.py and db.py (ALTER TABLE ... ADD COLUMN IF NOT EXISTS).

  confidence_summary    → Store as JSON blob in a new column on Candidate:
                          confidence_summary JSONB nullable.
                          RECOMMENDED: add Candidate.confidence_summary JSONB column.

  languages             → These are spoken languages (English C1, Italian B2),
                          not programming languages. No ORM model exists for them.
                          Store as JSON in a new column: Candidate.spoken_languages JSONB nullable.

  research              → No ORM model. If present, store as JSON in a new
                          Candidate.research JSONB nullable column.
                          This field is optional, so it can also be silently
                          skipped for now with a TODO comment.

  change_log            → Already handled by FactSheetChangeLog model. ✓

  skills                → No ORM model. Store as JSON in a new
                          Candidate.skills JSONB nullable column.
                          (MasterProfile has global_skills, but Candidate does not.)

SUMMARY OF NEW COLUMNS to add in models.py + db.py (prepare_database):
  Candidate.completion_status   VARCHAR(20) nullable
  Candidate.confidence_summary  JSONB nullable
  Candidate.spoken_languages    JSONB nullable

  ALTER TABLE candidates ADD COLUMN IF NOT EXISTS completion_status VARCHAR(20)
  ALTER TABLE candidates ADD COLUMN IF NOT EXISTS confidence_summary JSONB

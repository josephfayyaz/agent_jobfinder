# Phase F3 — Rejection Pattern Analytics

## Goal

After accumulating 5+ application outcomes, analyse the data to find patterns:
which role types convert best, whether the current score threshold is right,
what skill gaps appear most in rejections, and what the weekly pipeline funnel
looks like. Expose this as a single JSON endpoint.

---

## Hard Rules

- No Alembic. No new tables. Reads from existing `Application` + `JobPost` + `ResumeDraft`.
- Always conda ML.
- Minimum 5 applications with a non-null, non-"pending" status before returning analysis.
  If fewer, return `{"status": "insufficient_data", "required": 5, "current": N}`.
- No LLM calls in this service — pure Python aggregation.

---

## Key Models (already exist — read-only)

`Application` has: id, job_post_id, resume_track_id, resume_draft_id, status, created_at
  Status values: "pending", "applied", "responded", "interview", "offer", "rejected", "discarded"

`JobPost` has: id, title, company, location, seniority, description, extracted_metadata (JSONB)

`ResumeDraft` has: id, score (float), status, review_feedback (JSONB)

`ResumeTrack` has: id, slug, title, role_family

## 1. New Service `RejectionAnalyticsService`

Create `job_agent/services/rejection_analytics.py`:

```python
class RejectionAnalyticsService:
    def __init__(self, session: Session):
        self.session = session

    def analyse(self) -> dict:
        """
        Analyse application outcomes. Returns structured analytics dict.
        Raises ValueError if fewer than 5 completed applications exist.
        """
```

### What `analyse()` computes:

Pull all applications where status NOT IN ("pending"):

```python
apps = (
    session.query(Application)
    .filter(Application.status.notin_(["pending"]))
    .all()
)
```

If `len(apps) < 5`: raise `ValueError("insufficient_data")` with count attached.

Load related JobPost and ResumeDraft for each application.

Compute and return:

#### a. `funnel` — pipeline conversion counts
```json
{
  "total": N,
  "applied": N,
  "responded": N,
  "interview": N,
  "offer": N,
  "rejected": N,
  "discarded": N,
  "response_rate_pct": float,
  "interview_rate_pct": float,
  "offer_rate_pct": float
}
```
response_rate = (responded + interview + offer) / applied * 100
interview_rate = (interview + offer) / applied * 100
offer_rate = offer / applied * 100

#### b. `score_analysis` — draft score vs outcome
Group applications by score bucket (< 60, 60-74, 75-84, 85-100) and count outcomes per bucket.
```json
{
  "buckets": [
    {"range": "85-100", "count": N, "response_count": N, "interview_count": N},
    ...
  ],
  "recommended_threshold": int,
  "current_threshold": int,
  "threshold_note": "string explanation"
}
```
recommended_threshold: the lowest score bucket with response_rate >= 30%, or the best-performing bucket.

#### c. `by_track` — conversion by resume track
```json
[
  {"track_slug": "...", "track_title": "...", "applied": N, "responses": N, "conversion_pct": float}
]
```
Sort by conversion_pct descending.

#### d. `by_seniority` — conversion by job seniority level
```json
[{"seniority": "junior|mid|senior|intern|unknown", "applied": N, "responses": N, "conversion_pct": float}]
```

#### e. `skill_gaps` — recurring gaps in rejected applications
Read `review_feedback["gaps"]` from associated ResumeDraft records where
application status is "rejected". Flatten all gap strings, count occurrences.
```json
[{"gap": "gap text", "occurrences": N}]
```
Top 10 most frequent. Skip if no rejected applications with review_feedback.

#### f. `weekly_activity` — applications per ISO week
```json
[{"week": "2026-W12", "applied": N}]
```
Last 12 weeks.

#### g. `top_companies` — companies with most applications
```json
[{"company": "...", "applied": N, "best_status": "interview|offer|responded|rejected"}]
```
Top 10.

## 2. New Endpoint in `main.py`

```python
@app.get("/analytics/rejection-patterns")
def rejection_patterns(db: Session = Depends(get_db)):
    """
    Analyse application outcomes for patterns and recommendations.
    Returns 200 with analysis or 200 with insufficient_data status.
    """
    from job_agent.services.rejection_analytics import RejectionAnalyticsService
    svc = RejectionAnalyticsService(db)
    try:
        return svc.analyse()
    except ValueError as exc:
        if "insufficient_data" in str(exc):
            # Get count from the exception or re-query
            count = db.query(Application).filter(Application.status.notin_(["pending"])).count()
            return {"status": "insufficient_data", "required": 5, "current": count}
        raise HTTPException(status_code=500, detail=str(exc))
```

# Stage 06 — Marketing Copy, Help, and Conversion Experiments

## Goal

Reduce onboarding drop-off and make the token/key story feel trustworthy instead of technical.

## Core Message

Use this product framing consistently:

- `Use your own provider account`
- `Your key stays on your machine`
- `You pay OpenAI or Anthropic directly`
- `Switch providers any time`
- `Local LLM is available later if you want lower long-run cost`

## Help Center Content

Add short, practical guides:

- `What is the difference between ChatGPT/Claude subscriptions and API billing?`
- `How much does a typical job search cost?`
- `How do I switch providers if credits run out?`
- `When should I use local LLM instead?`

## Suggested Experiments

### Experiment A — Provider choice framing

Test:

- `Choose your AI provider`
vs
- `Choose how Job Agent should run`

### Experiment B — Cost framing

Test:

- model names first
vs
- `Economy / Balanced / Premium` first

### Experiment C — Local LLM placement

Test:

- local shown in onboarding step
vs
- local shown only after first successful cloud setup

## Metrics to Track

- provider setup completion rate
- key test success rate
- time to first successful draft
- fallback trigger rate
- users who enable both providers
- users who later adopt local LLM

## Recommendation

The most important KPI is:

`time from first visit to first successful draft`

If the user reaches a good draft quickly, billing complexity becomes much easier to tolerate.

## Acceptance Criteria

- help content exists in product
- provider onboarding has measurable completion metrics
- experimentation can happen without reworking the whole stack

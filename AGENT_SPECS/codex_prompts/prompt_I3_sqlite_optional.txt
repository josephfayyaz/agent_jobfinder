PHASE I3 — SQLite as Optional Database Backend
===============================================

## Goal

Replace the Docker PostgreSQL requirement with embedded SQLite for users who don't
have Docker. SQLite lives as a single file in the project folder — zero external
services, zero setup, works on any machine with Python.

PostgreSQL via Docker remains the recommended production setup. SQLite is the
default for first-time / non-technical users.

---

## Key Design Decision

- `DATABASE_URL` in `.env` / `user_settings.yml` controls which backend is used.
- Default (if unset): `sqlite:///./job_agent.db` (file in project root).
- Docker PostgreSQL: `postgresql+psycopg://job_agent:job_agent@localhost:5432/job_agent`.
- The app detects which backend is active and shows it in `/health`.
- **No Alembic.** `prepare_database()` via `create_all()` already works for both backends.

### 2. `job_agent/db.py`

SQLAlchemy supports SQLite natively but needs two config tweaks:

```python
from sqlalchemy import create_engine, event, text
from sqlalchemy.orm import sessionmaker, DeclarativeBase

def _make_engine(url: str):
    is_sqlite = url.startswith("sqlite")
    if is_sqlite:
        engine = create_engine(
            url,
            connect_args={"check_same_thread": False},
            pool_pre_ping=True,
        )
        # Enable WAL mode for concurrent reads (worker + API simultaneously)
        @event.listens_for(engine, "connect")
        def _set_sqlite_pragma(dbapi_conn, _record):
            cursor = dbapi_conn.cursor()
            cursor.execute("PRAGMA journal_mode=WAL")
            cursor.execute("PRAGMA foreign_keys=ON")
            cursor.close()
        return engine
    else:
        return create_engine(url, pool_pre_ping=True)
```

Replace the existing `engine = create_engine(...)` with `engine = _make_engine(settings.database_url)`.

### 3. `job_agent/db.py` — `prepare_database()`

The existing `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` syntax is PostgreSQL-only.
SQLite uses `ALTER TABLE ADD COLUMN` (no `IF NOT EXISTS`).

Wrap each ALTER in a try/except for SQLite compatibility:

```python
def _safe_add_column(conn, table: str, column: str, col_type: str) -> None:
    try:
        conn.execute(text(f"ALTER TABLE {table} ADD COLUMN {column} {col_type}"))
    except Exception:
        pass  # Column already exists — SQLite raises, PostgreSQL uses IF NOT EXISTS
```

Replace all `conn.execute(text("ALTER TABLE ... ADD COLUMN IF NOT EXISTS ..."))` with:
```python
_safe_add_column(conn, "table_name", "column_name", "COLUMN_TYPE")
```

### 4. `job_agent/db.py` — JSONB compatibility

JSONB is PostgreSQL-specific. SQLite uses TEXT for JSON columns.
In models.py, JSONB is already compiled to TEXT for SQLite via the conftest fixture.
Apply the same workaround in db.py for production code:

In `db.py`, add at the top:

```python
from sqlalchemy.dialects.postgresql import JSONB
from sqlalchemy.ext.compiler import compiles
from sqlalchemy.types import Text

@compiles(JSONB, "sqlite")
def _compile_jsonb_sqlite(element, compiler, **kw):
    return "TEXT"
```

def test_health_reports_db_backend(client):
    resp = client.get("/health")

def test_safe_add_column_does_not_raise_on_duplicate(db_session):
    from sqlalchemy import text
    from job_agent.db import _safe_add_column

    with db_session.bind.connect() as conn:
        _safe_add_column(conn, "job_posts", "title", "TEXT")
        _safe_add_column(conn, "job_posts", "title", "TEXT")  # duplicate — should not raise

## Migration Guide (for existing PostgreSQL users)

Add to `README.md`:

```
## Switching from PostgreSQL to SQLite

1. Export your data: pg_dump job_agent > backup.sql
2. Update .env: DATABASE_URL=sqlite:///./job_agent.db
3. Restart the app — tables are recreated automatically.

To switch back to PostgreSQL:
1. Set DATABASE_URL=postgresql+psycopg://...
2. Restart — the app reconnects to PostgreSQL automatically.
```
